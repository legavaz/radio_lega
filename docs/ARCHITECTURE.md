# Архитектура

Документ объясняет **почему** код устроен именно так. Если решение кажется
странным — скорее всего, за ним стоит конкретная проблема, найденная на тестах.

## Общая схема

```
┌─────────────────────────────────────────────┐
│ UI (Compose)                                │
│  AppRoot: список, мини-плеер, полный плеер   │
│  RadioViewModel: состояние + MediaController│
└───────────────┬─────────────────────────────┘
                │ MediaController (IPC-канал media3)
┌───────────────▼─────────────────────────────┐
│ RadioService (MediaSessionService)          │
│  ExoPlayer · MediaSession · SleepTimer      │
└───────────────┬─────────────────────────────┘
                │
        HTTP-потоки станций (HLS / ICY)
```

Плюс два общих объекта в процессе:

| Объект | Зачем |
|---|---|
| `PlaybackRegistry` | сервис по `mediaId` достаёт станцию со всеми потоками — для фолбэка |
| `SleepTimerState` | UI читает обратный отсчёт, не поднимая канал связи |

## Почему один модуль

В проекте ~15 файлов. Разбиение на `:feature:*` и `:core:*` окупается, когда
над кодом работает больше одного человека или когда сборка становится долгой.
Сейчас модульность добавила бы только навигацию по папкам.

Переходить на модули имеет смысл, когда появится: второй экран со своим
состоянием, отдельная фича виджета, и захочется параллельной сборки.

## Почему без Room

- Каталог — **один список**, который при обновлении заменяется целиком.
- Избранное — **набор id**, а не таблица.
- История прослушиваний пока не нужна.

Поэтому: JSON-файл в `filesDir` (каталог) + DataStore Preferences (избранное,
настройки, последняя станция). Это меньше кода, нет KSP и миграций.

**Когда менять:** появится история, поиск по срезу «все станции мира»
(10 000+), пагинация из БД. Тогда меняется только `StationStore` — остальной
код работает через него.

## Воспроизведение

### Сервис, а не ViewModel

Экран умирает при сворачивании, музыка — нет. Поэтому `ExoPlayer` живёт в
`MediaSessionService`, а UI подключается через `MediaController`.

### Фолбэк потоков в сервисе

UI отправляет `MediaItem` с `mediaId`. Полный список потоков сервис берёт из
`PlaybackRegistry` по этому id. Поэтому при ошибке потока он может
переключиться на резервный адрес **даже когда экран выключен** — UI в этом не
участвует.

### Команды через MediaSession

Таймер сна управляется `SessionCommand` (`ru.lega.radio.SLEEP_TIMER`), а не
прямым вызовом методов сервиса. Причина: команду можно повесить на кнопку в
уведомлении, виджете или на гарнитуре без переделки. Состояние обратно
отдаётся через `SleepTimerState` — это дешевле, чем второй канал.

### Почему `usesCleartextTraffic=true`

Часть радиостанций до сих пор отдаёт поток по `http://`. Без этого флага они
не играют на Android 9+.

## Каталог

### Пагинация по 12

Сервер Radio Browser рвёт chunked-ответы длиннее ~18 КБ. Проверено: `curl` с
ПК, с телефона, из приложения — везде обрыв на середине JSON. Лечение:
маленькие страницы `limit=12&offset=N`, каждая сразу уходит в UI, неудачная
страница повторяется один раз и пропускается.

### IPv4-only DNS

У `radio-browser.info` есть AAAA-записи, но у оператора/роутера нет маршрута в
IPv6. Java резолвит AAAA первым, `connect()` висит до таймаута. `Ipv4Dns`
фильтрует адреса до `Inet4Address`.

### HTTP/1.1

В этой сети HTTP/2 «зависает»: заголовки приходят, тело не читается (стек
`Http2Stream`). Для обычного REST выгоды от h2 нет — фиксируем HTTP/1.1.

## Логотипы

Четыре шага, потому что у половины станций (особенно российских) `favicon`
пустой:

1. `favicon` из каталога
2. иконка по домену `homepage` (DuckDuckGo)
3. иконка по домену `homepage` (Google)
4. иконка по домену аудиопотока
5. цветная буква (цвет стабилен — от хеша названия)

Coil кэширует скачанное на диск, поэтому повторно иконки не тянутся.

## Свои станции

Станция, добавленная по URL, хранится в `DataStore` строкой JSON — вместе с
ними же лежит и флаг `custom = true`, чтобы UI отличал их от каталога:

```kotlin
Station(
    id = "user:<url>",        // id по адресу: повторное добавление не дублируется
    name = ...,
    streams = listOf(Stream(url, isHls = url.endsWith(".m3u8"))),
    custom = true,
)
```

Почему не отдельная таблица: своих станций обычно единицы, поиск и сортировка
по ним не нужны, а весь код уже работает через `StationStore`. Вкладка
**«Мои»** — это просто ещё одно значение `CatalogFilter`, которое не ходит в
сеть.

Удаление — долгое нажатие с подтверждением. Воспроизведение при этом не
прерывается: станция удаляется из списка, но текущий `MediaItem` живёт в
сервисе.

## Сборка и CI

`gradle.properties` **не должен содержать машинно-зависимых путей.** Первая
версия CI упала именно на этом:

```
Value 'E:\project\tools\jdk21' given for org.gradle.java.home
Gradle property is invalid (Java home supplied is invalid)
```

Локальный JDK передаётся через переменную `JAVA_HOME` (её ставят `install.ps1`
и команды из README), а `org.gradle.java.home` из файла убран — иначе сборка
работает только на машине автора.

`.github/workflows/build.yml` на каждый пуш в `main`: JDK 21 → Android SDK 35 →
`gradlew test` → `assembleDebug` → APK в артефакты.


## Восстановление последней станции

`DataStore` хранит станцию целиком (JSON) и флаг `last_playing`.

- Играла → при старте `setMediaItem` + `prepare()` + `play()`.
- Стояла на паузе → только `setMediaItem`, плеер остаётся в `IDLE`
  (уведомление не показывается, пока пользователь не нажмёт play).

Запись происходит в двух местах: при старте станции и при каждом изменении
`isPlaying` — так ловятся и пауза от таймера сна, и пауза при отключении
наушников.

## Таймер сна: затухание и встряхивание

### Затухание

Последние 60 секунд громкость идёт линейно к нулю:

```kotlin
player.volume = when {
    remaining == null -> 1f                       // таймер выключен
    remaining <= 0L -> 0f
    remaining < SleepTimer.FADE_MS -> remaining.toFloat() / SleepTimer.FADE_MS
    else -> 1f
}
```

Отдельный цикл не нужен: таймер и так тикает раз в секунду, поэтому подписка
на `SleepTimerState.remainingMs` пересчитывает громкость на каждом тике.
`player.volume` — громкость приложения, системную мы не трогаем.

Проверено по логам: `1.00 → 0.92 → 0.83 → 0.75 → … → 0.08 → 0.00`, затем пауза.

### Встряхивание

`ShakeDetector` слушает `TYPE_LINEAR_ACCELERATION`, а если его нет — обычный
акселерометр с вычитанием гравитации (high-pass фильтр).

| Параметр | Значение | Почему так |
|---|---|---|
| Порог | 18 м/с² | спокойные движения дают 3–8, встряхивание — 20+ |
| Пиков в окне | 2 за 350 мс | одиночный удар (положили телефон) не считается |
| Пауза после срабатывания | 2 с | одно движение не даёт серию сбросов |

Датчик регистрируется **только в последнюю минуту** — когда идёт затухание и
есть смысл продлить. Всё остальное время он выключен: и батарея целее, и
случайные движения не сбрасывают таймер. Если после встряхивания таймер
перезапустился (осталось снова много времени), датчик тут же снимается.

Чтобы это было понятно без документации, обратный отсчёт в последнюю минуту
**становится жёлтым** — в полном плеере и в индикаторе мини-плеера. Жёлтый =
«можно трясти».

По событию: `sleepTimer.restart()` (тот же период, что был выбран),
`player.volume = 1f` **мгновенно**, затем короткий звук маракасов — если
воспроизведение активно. Если таймер не идёт, встряхивание игнорируется.

### Звук маракасов

Своего сэмпла нет, а брать чужой нельзя, поэтому файл **сгенерирован
синтетически**: `res/raw/maracas.wav` — два шумовых всплеска с
экспоненциальным затуханием (τ = 24 мс) и high-pass фильтром, 44.1 кГц,
16 бит, ~230 мс. Играется через `SoundPool`.

## ICY-«сейчас играет» — почему откатили
Была написана обёртка `IcyDataSource` над `HttpDataSource`: читает
`icy-metaint`, вырезает блоки метаданных, отдаёт `StreamTitle` в UI.

**Что пошло не так:** на границе метаданных код синхронно дочитывал блок
через цикл `read()`. Если сервер отдавал блок частями или `read()` возвращал
`-1`, цикл выходил раньше, и остаток метаданных попадал в аудио. После этого
байтовый поток навсегда смещался относительно границ `metaint` — декодер
получал мусор вместо кадров. Слышно как «заикание».

**Как делать правильно:**

1. **Конечный автомат без блокирующих дочитываний.** `read()` никогда не ждёт
   метаданные целиком: копит их в буфер между вызовами, возвращает `0` только
   когда данных нет вообще, явно обрабатывает `-1`, сбрасывает состояние при
   реконнекте и смене станции.
2. **Или не трогать транспорт.** Держать отдельный лёгкий парсер на копии
   потока и отдавать `IcyInfo` в плеер как метаданные. Если парсер упадёт —
   пропадёт только название трека, звук не пострадает.

Второй путь безопаснее и предпочтительнее.

## Экономия батареи

Honor/Huawei/Xiaomi замораживают приложения в фоне даже с foreground-сервисом.
Единственное лечение — исключение из оптимизации батареи, которое пользователь
выдаёт вручную. Показываем баннер, пока `isIgnoringBatteryOptimizations()`
возвращает `false`.

Проверка на Honor ELI-NX9: диалог системы называется «Игнорировать оптимизацию
батареи?», кнопка подтверждения — «Пропустить». После нажатия пакет попадает
в `dumpsys deviceidle whitelist`.
